Schedules

Times are in the hub's time zone. A "switch" stops every other model on the same host, drops its page cache, then starts the chosen one.

⏸ All schedules are paused — nothing will start or stop on its own. “Run now” still works.

Planned runs

Each row is one model: a block means running (1), a gap means stopped (0). a schedule fires on that model, “stop all” / “free memory”. Assumes every scheduled action succeeds. Click a block or marker to edit its schedule.

Hosts

This dashboard controls models on every machine listed here. To add another machine (e.g. a Mac Studio), install the manager there in agent mode (DGXM_MODE=agent and a long random DGXM_AGENT_TOKEN), then add it with its URL and that token.

Ports & endpoints

Every recipe's port per host. The API of a running model is at its endpoint (OpenAI-compatible for vLLM, SGLang, llama.cpp and MLX). Recipes that share a port on the same host can't run at the same time.

HostPortRecipeStatusEndpoint

Images

The Docker images your recipes use and whether each host has them. ⬆ marks a newer tag of the same image that is already on that host – click it to switch that host's recipes to it (a running model keeps the old image until you restart it).

Weights

Register model weights once and set where they live on each host. A recipe that picks them writes {weights} (e.g. the volume {weights}:/model:ro) and gets that host's path when it starts – so moving a recipe to another host needs no edits. Click a cell to set or change a path.

Used by recipes

What every model recipe references and whether each host has it locally: the host folder a container path like /model is mounted from (Volumes), the Hugging Face cache for org/name ids, or a file in DGXM_MODEL_DIR (default ~/models). ✗ missing means the weights are not on that host yet.

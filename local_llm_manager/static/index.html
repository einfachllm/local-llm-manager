Schedules

Times are in the hub's time zone. A "switch" stops every other model on the same host, drops its page cache, then starts the chosen one.

⏸ All schedules are paused — nothing will start or stop on its own. “Run now” still works.

Planned runs

Each row is one model: a block means running (1), a gap means stopped (0). a schedule fires on that model, “stop all” / “free memory”. Assumes every scheduled action succeeds. Click a block or marker to edit its schedule.

Hosts

This dashboard controls models on every machine listed here. To add another machine (e.g. a Mac Studio), install the manager there in agent mode (DGXM_MODE=agent and a long random DGXM_AGENT_TOKEN), then add it with its URL and that token – or also set DGXM_HUB_URL= this dashboard's address there: the machine then asks to be added and shows up below.

Ports & endpoints

Every recipe's port per host. The API of a running model is at its endpoint (OpenAI-compatible for vLLM, SGLang, llama.cpp and MLX). Recipes that share a port on the same host can't run at the same time. Running models show live output/input speed, requests and KV-cache use.

Images

The Docker images your recipes use and whether each host has them. ⬆ marks a newer tag of the same image that is already on that host – click it to switch that host's recipes to it (a running model keeps the old image until you restart it).

Weights

One row per model, one column per host: ✓ it is there, ✗ not found, + set path if you haven't said where it is. Click a cell to change the path. In a recipe, pick the model under Weights – each host then uses its own path.

Paste a YAML recipe or a shell script (docker run … works too).
          Scripts are checked first, then run in a restricted bash: only read-only text tools run, a fake
          docker records the final command, and everything else is skipped. Recipe files are read
          directly.

Recipe file

      

        
A compact recipe file: only settings that differ from the framework
          preset are written down. Volumes, environment, extra Docker flags and server arguments are all included,
          so importing it on another manager gives the same recipe (pick the host after importing). You can edit
          the file here and use Apply to editor to load your changes without saving.
